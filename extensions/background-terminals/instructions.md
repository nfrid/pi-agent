- Use `background_start` for non-interactive commands that should outlive the current turn; use ordinary bash for short commands.
- `background_start` defaults to `kind: "task"`. A task keeps the current request open until its terminal result enters model context. Use `kind: "service"` for a passive long-lived process. A service does not hold the request open unless it has output watches.
- Watches supplied to `background_start` or added with `background_watch` observe future output only and never kill the process. Their match, timeout, end, or removal outcome must enter model context before the request can close. A task still waits for process exit after a watch matches. The eight-watch limit includes retained settled watches; use `background_unwatch` to remove unneeded watches before adding more.
- When a required result is the only remaining dependency, stop calling tools and send at most one brief assistant commentary message saying you are waiting. End the current response without a `final_answer`; do not repeat the notice before the result arrives. Reserve `final_answer` for substantive answers, including a real early answer when optional work remains pending. Do not use `background_list` or `background_peek` just to check progress; completion resumes automatically.
- Background jobs survive parent Pi session shutdown and recreation; use `background_stop` explicitly when a job should terminate.
